# 文章反馈、积分和卡密兑换

任何已发布文章的底部都支持使用问题、Bug 和功能建议。登录用户可填写版本、设备、复现步骤及最多 3 张截图。原评论功能继续提供普通讨论。

新反馈默认待处理，审核前只对本人和管理员可见。用户可取消公开许可；管理员无法公开私密反馈。前台展示用户署名、状态、开发者回复、时间线、解决版本和奖励。

后台入口：`/admin/feedback`（需求与 Bug）、`/admin/points`（积分兑换）。用户入口：`/dashboard/points`，也可从账户页或文章底部进入。

## 奖励和兑换

- 默认采纳 +10，开发完成追加 +40；后台可设置 0–10000。提交、回复和公开反馈不会产生奖励。
- 同一反馈的采纳和完成阶段各奖励一次。直接完成会补齐采纳奖励；重新打开或重复保存不重复奖励。发放后的奖励不因状态变更自动收回。
- 积分与账户现金余额独立。用户行锁、唯一流水键和事务确保余额、流水及奖励一致。
- 兑换商品由管理员配置，默认关闭。创建后按权益类型生成本站卡密或导入实际外部卡密；添加库存、设置积分价格并开放兑换。
- 每个积分商品使用独立的隐藏 CardPackage，沿用 Cards、Order、OrderDelivery 和卡密核销功能。现金下单接口排除积分商品；积分兑换创建金额 0 的已发货订单，不触发现金支付。
- 积分扣除、发卡、库存占用和兑换记录在同一事务中。库存不足、解密失败或余额不足会整体回滚。相同用户和 requestKey 重试返回原发卡记录，不重复扣分。requestKey 必须是 UUID。
- 卡号、卡密仅在本人积分兑换记录和本人订单中显示，接口设置 private/no-store。

## 数据与配置

迁移只给 users 增加默认 0 的 points 字段，并新增 article_feedbacks、feedback_events、feedback_images、point_entries、point_rewards、point_redemptions；不改变原余额、评论、订单或卡密数据。

```env
FEEDBACK_UPLOAD_DIR="/persistent/private/feedback-images"
POINT_CARD_KEY="至少 32 字符的随机密钥"
```

积分专属卡密的哈希和密文使用 `points-v1:` 格式和 POINT_CARD_KEY；原卡密沿用原 CARD_SECRET_SALT/CARD_DELIVERY_KEY。独立密钥不会恢复缺失的旧密钥，也不会改写旧卡密。备份须同时保留数据库、独立密钥和截图文件。

截图仅接收真实 JPEG/PNG/WebP/GIF，输入最多 4 MiB，通过 Sharp 进行像素限制、旋转和压缩，移除原始元数据，输出 WebP；不接受外部图片 URL 或用户指定文件路径。截图存储在静态 uploads 外，由受权限保护的接口提供。隐藏、未绑定及草稿文章截图对第三方返回 404。

每用户每天最多 5 条反馈及 15 张截图；接口另有限流。上传未提交的图片 24 小时后不可绑定，下次同用户上传时清除其过期未绑定图片（最多 100 张）。已提交的图片保留为反馈记录。没有新增自动任务。

Nginx 应关闭反馈和积分接口的缓存，截图上传 body 限制建议 5 MiB。其他服务的设置保持不变。

## 状态说明

待处理可转采纳、开发中、完成或暂不采纳；采纳可转开发中、完成或暂不采纳；开发中可转完成或暂不采纳；完成可重新转开发中；暂不采纳可重新转待处理或采纳。变更状态必须填写说明。状态仅表达开发者处理进度，完成不等于用户已经安装了该版本。
